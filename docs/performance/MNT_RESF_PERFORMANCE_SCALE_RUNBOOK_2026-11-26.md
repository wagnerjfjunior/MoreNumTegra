## 3. Repeatable execution per route

1. Resolve GitHub main, Vercel production exact runtime SHA and alias; read SFJM governance and page-specific frozen baseline. Verify explicit slice scope and merge authorization later. Record URL, template, status, baseline SHA, protected contracts and rollback path. Capture five comparable mobile Lighthouse runs (same version, viewport, throttling, initial/cold state and consent), record timestamps, screenshots, metric distributions, audits and LCP element/request. Desktop diagnostic separately. Inspect HAR/trace locally with no PII. Do not conflate reported savings with actual transfer.
2. Audit images: rendered slot at 360/390/430/900/1440, DPR 1/2/3, intrinsic size/aspect, currentSrc, original URL, source bytes, licensing/provenance, focal point, cache, network priority and whether above fold. Inventory existing derivatives and manifest before creating more. Optimize largest bottleneck first. Preserve actual project identity, plans and captions.
3. Generate only useful WebP variants from approved source (Pillow or equivalent reproducible tooling; no upscale; use LANCZOS or equivalent; choose quality by visual comparison). Example V7 settings: hero 1200x630 -> 960x504 q70, Rua 1920x1080 -> 768x432 q65, transparent logo 288x162. Typical RESF project variants 640/828 where useful; widths derived from slot/DPR and native detail. Keep original, alpha, aspect/focal point and authorized attribution. For plan diagrams/text prioritize readability, not blanket lossy compression. Record source/variant paths, SHA256 or Git blob hash, dimensions, bytes, quality/encoder and date; update manifest without rewriting prior records. Budget preferred hero <=100 KiB, review >150 KiB, gallery main <=120 KiB, thumbnails <=30 KiB. No large original/video/gallery library in repo. Existing /assets cache max-age 604800 seconds; verify real response headers, avoid unversioned replacement; use versioned paths if changing bytes. Upload to authorized GDigital/S3 or small project-owned assets; verify HTTP 200, image type and hash. Reuse common logo where contract permits.
4. Wire hero in initial semantic HTML, eager/high priority, explicit intrinsic dimensions, responsive srcset/sizes for actual slot or picture/source for art direction; preserve direct-child requirements. Preload only measured LCP bottleneck, with identical candidate selection and no duplicate request. Secondary images/gallery lazy/async below fold; preserve sizes, ALT, captions, image state on scene changes, keyboard/touch. No blanket lazy on LCP; no blanket preload. Keep OG/Twitter/JSON-LD/SEO canonical original as governed. Keep video facade/fallback and consent contract. No changes to Form46/47, CTA, tracking, cookies, prices, facts, schema ownership or region channels.
5. Isolate CSS/JS work after media A/B only if evidence warrants: inspect render-blocking request chain, long-task stack, filmstrip/trace for SI variation and forced reflow; do not defer essential styles blindly, remove DOM/content, delay essential consent, or hide UI to game scores. One cause per slice; verify accessibility, no flash of unstyled content, no layout shift. No blanket minifier or framework migration.
6. Verify exact-head static gates (schema/metadata, facts, media, channel, Form, consent, agentic, accessibility and existing required CI). For frozen/snapshot pages obtain explicit exact exception before any validator or protected HTML change; do not loosen contracts. Browser QA: currentSrc/HTTP/cache/no duplicate, crop and readable floorplans, mobile filters/nav, CTA/WhatsApp, video consent and fallback, form validation/error paths, no real lead unless explicitly authorized, desktop visual parity. Record pre-existing debt separately. Use LOCAL_LIVE_SYNC or approved preview per current governance; do not invent preview availability. Owner approval and explicit PR merge authorization required. Confirm Vercel READY, exact runtime SHA, public alias and smoke. Repeat same five-run mobile battery, compare median/worst/range, record all results; if regression or functional break, stop and isolate/revert exact change with approval. Never roll back unrelated releases silently.
7. Save receipt per route: evidence class, source/target SHA, deployment, PR/CI, asset manifest, before/after metrics, screenshot/trace references, visual/functional acceptance, field data or UNKNOWN, residuals, rollback. Page status: INVENTORIED / BASELINED / CANDIDATE / CI_PASS / DEPLOYED / LAB_VALIDATED / FUNCTIONAL_ACCEPTED / BLOCKED (independent flags, not interchangeable).

## 4. Rollout waves (proposed, not authorized runtime work)

Wave 0: finish two home PSI runs, visual and functional acceptance; inventory public canonical URLs and classify gaps. Wave 1: choose one unlocked SP project, one regional hub, one editorial article using live baseline and GSC demand where available; establish reproducibility. Wave 2: small groups of 3–5 similar pages with independent per-page gates, measure before/after and stop on regression. Wave 3: RJ and special templates isolated; validate distinct channels and interaction modules. Wave 4: remaining pages prioritized by traffic, LCP, image waste and conversion relevance. Do not revisit already compliant pages for score alone. No blanket rewrite, no mass PR or bulk upload. Separate approval for each slice and PR. Keep baseline references, no invented inventory counts. Recommended tracking fields: route/family, main/runtime SHA, LCP element, baseline/candidate 5-run medians and ranges, assets/bytes/hash, owner scope, CI, visual/form/CTA, deployment, residual, rollback, field metrics.
